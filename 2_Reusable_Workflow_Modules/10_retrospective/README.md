# Module: retrospective

> Placeholder (v0.1.0).

## Purpose
Convert lived experience into changes to L1/L2/L3 — not a feel-good ritual.

## Inputs
- BuildLog, Verification, Metrics report, Risk register.

## Outputs
- Retro note: keep / change / drop.
- Concrete edits proposed to L1 / L2 / L3 (PRs against the Factory).

## Acceptance Criteria
- Each "change" or "drop" item points to a specific edit target (file + section).
- At least one item is filed back into the Factory or marked "no Factory change needed" with reason.

## Control Points
Start (retro scope agreed) → Automated (action-tracker) → Human if Critical → Final (proposals filed).

## Checklist
- [ ] Items targeted at concrete files
- [ ] Owners assigned
- [ ] Follow-up tracked

## Anti-patterns
- Lessons that never become edits.
- Blame-oriented retros.
