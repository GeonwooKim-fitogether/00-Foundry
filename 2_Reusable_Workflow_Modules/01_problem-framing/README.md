# Module: problem-framing

> Placeholder (v0.1.0). Standard structure from `_module_template.md`.

## Purpose
Turn a vague intent into a sharply stated problem worth solving — for whom, why now, and what would make it false.

## Inputs
- Stakeholder request / observation / opportunity.
- Existing project ontology (if any).

## Outputs
- A first draft of `NPI_Brief.md` Problem section.
- Candidate Affected Objects.

## Acceptance Criteria
- Problem statement is one paragraph and names the user, the pain, and the trigger.
- At least one falsification condition (what would prove this is the wrong problem) is recorded.

## Control Points
Start (problem agreed) → Automated (peer/AI sanity checks) → Human if Critical → Final (Brief draft accepted).

## Checklist
- [ ] User and pain identified
- [ ] Falsification condition stated
- [ ] Candidate Objects listed

## Anti-patterns
- Jumping to solutions before the problem is stated.
- Framing the problem in terms of a chosen tool.
